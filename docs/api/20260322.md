# Scheduled / SalesOpen Draw 清單 API

## 用途說明
提供後台查詢目前 **有效狀態** 為 `Scheduled` 或 `SalesOpen` 的 Draw 清單，供前端顯示即將開賣與販售中的期數。

> `EffectiveStatus` 不是直接取資料表 `Status` 欄位，而是依照 Draw Aggregate 的 `GetEffectiveStatus(DateTime utcNow)` 規則，在查詢層以 `utcNow` 參數計算得出。

## Request
- **Method**: `GET`
- **Route**: `/admin/gaming/draws/scheduled-sales-open`

## 權限需求
- `GAMING:DRAW:MANAGE`

## Query string / path 參數
此 API 不需要 query string 或 path 參數。

## 排序規則
固定以：
1. `SalesOpenAt ASC`
2. `DrawAt ASC`

## Response JSON 範例
```json
[
  {
    "id": "8d4c9107-3a8c-4f5f-a8cd-b33f5b7b54ec",
    "gameCode": "539",
    "drawCode": "539-260322001",
    "salesOpenAt": "2026-03-22T08:00:00Z",
    "salesCloseAt": "2026-03-22T12:00:00Z",
    "drawAt": "2026-03-22T12:05:00Z",
    "effectiveStatus": "Scheduled"
  },
  {
    "id": "1bca65c5-2dd6-4d72-b68a-686b4c79c8c3",
    "gameCode": "539",
    "drawCode": "539-260322002",
    "salesOpenAt": "2026-03-22T09:00:00Z",
    "salesCloseAt": "2026-03-22T13:00:00Z",
    "drawAt": "2026-03-22T13:05:00Z",
    "effectiveStatus": "SalesOpen"
  }
]
```

## 欄位說明
| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| `id` | `guid` | Draw 識別碼 |
| `gameCode` | `string` | 遊戲代碼 |
| `drawCode` | `string` | 期數代碼 |
| `salesOpenAt` | `string(date-time)` | 售票開始時間（UTC） |
| `salesCloseAt` | `string(date-time)` | 售票截止時間（UTC） |
| `drawAt` | `string(date-time)` | 開獎時間（UTC） |
| `effectiveStatus` | `string` | 依有效狀態規則計算出的狀態，只會是 `Scheduled` 或 `SalesOpen` |

## EffectiveStatus 說明
查詢層會先排除以下資料：
- `Status = Cancelled`
- `SettledAtUtc IS NOT NULL`
- `DrawnAt` 對應欄位已有值
- `WinningNumbersRaw` 已有非空白內容
- `IsManuallyClosed = true`
- `utcNow >= SalesCloseAt`

接著在 `SELECT` 內計算：
- `utcNow < SalesOpenAt` => `EffectiveStatus = Scheduled`
- 否則 => `EffectiveStatus = SalesOpen`

因此前端應以 `effectiveStatus` 為準，不要直接以資料表 `status` 概念推測畫面狀態。

## 分頁說明
此 API 目前**不分頁**，沿用既有 Draw 列表查詢風格，直接回傳符合條件的清單。

## 前端串接注意事項
1. API 回傳的時間皆為 UTC，前端若需顯示本地時區請自行轉換。
2. `effectiveStatus` 已在後端查詢層完成計算，前端不需要再自行複製一份 Draw 狀態推導邏輯。
3. 此 API 只會回傳有效狀態為 `Scheduled` / `SalesOpen` 的 Draw；若 Draw 已封盤、已開獎、已結算、已取消，皆不會出現在結果中。
4. 若後續資料量增大，可考慮針對 `(tenant_id, sales_close_at, sales_open_at)` 與排除條件相關欄位評估複合索引或 partial index；本次未建立 migration。
