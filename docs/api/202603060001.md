# Member Tag × TicketClaimEvent 技術規格 v1

> 狀態：Draft v1（可開工）  
> 日期：2026-03-06  
> 範圍：會員 Tag 能力、TicketClaimEvent 的 Tag 受眾限制、可見活動與可領資格的即時一致性

---

## 1. 目標與決策

本版本先落地以下明確決策：

1. **Tag 在租戶內全域唯一**：唯一鍵為 `(tenant_id, tag_code)`。
2. **刪除語義採停用**：Tag 不做硬刪除，改以 `is_active = false` 停用。
3. **活動生效中允許修改 Tag 條件**：允許更新，且必須寫入審計紀錄。
4. **命中規則採 ANY**：會員具備任一命中 Tag 即符合資格。
5. **會員 Tag 變更需立即生效**：
   - 立即影響「可見活動」查詢。
   - 立即影響「Claim 可領資格」檢核。
6. **高流量初版先靠 SQL 索引，不做快取**。

---

## 2. Non-Goals（v1 不做）

- 不做 Tag 階層（父子 Tag）。
- 不做 Tag 表達式（AND/OR/NOT 複合邏輯），僅支援 ANY。
- 不做 Redis 快取與事件最終一致性投影。
- 不做多語系 Tag 顯示名稱（僅保留單一 display_name）。

---

## 3. 資料模型（DB Schema）

> 命名以 PostgreSQL + snake_case 為準。

### 3.1 `member_tags_catalog`

租戶內 Tag 主檔（全域唯一 + 停用）

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | uuid PK | Tag id |
| tenant_id | uuid not null | 租戶 |
| tag_code | varchar(64) not null | 規格碼（建議 lowercase） |
| display_name | varchar(128) not null | 顯示名稱 |
| is_active | boolean not null default true | 啟用/停用 |
| created_at_utc | timestamptz not null | 建立時間 |
| updated_at_utc | timestamptz not null | 更新時間 |

索引與約束：
- `UNIQUE (tenant_id, tag_code)`
- `INDEX (tenant_id, is_active)`

### 3.2 `member_tag_bindings`

會員與 Tag 的綁定關係（多對多）

| 欄位 | 型別 | 說明 |
|---|---|---|
| tenant_id | uuid not null | 租戶 |
| member_id | uuid not null | 會員 |
| tag_id | uuid not null | 對應 `member_tags_catalog.id` |
| created_at_utc | timestamptz not null | 綁定時間 |
| created_by_user_id | uuid null | 操作者 |

索引與約束：
- `PRIMARY KEY (tenant_id, member_id, tag_id)`
- `INDEX (tenant_id, member_id)`
- `INDEX (tenant_id, tag_id)`

### 3.3 `ticket_claim_event_tag_rules`

TicketClaimEvent 與可領 Tag 規則（ANY）

| 欄位 | 型別 | 說明 |
|---|---|---|
| tenant_id | uuid not null | 租戶 |
| event_id | uuid not null | 活動 |
| tag_id | uuid not null | 可領取 tag |
| created_at_utc | timestamptz not null | 建立時間 |
| created_by_user_id | uuid null | 操作者 |

索引與約束：
- `PRIMARY KEY (tenant_id, event_id, tag_id)`
- `INDEX (tenant_id, event_id)`
- `INDEX (tenant_id, tag_id)`

### 3.4 停用 Tag 與相容策略

- 停用 `member_tags_catalog.is_active = false` 後：
  - 不可再被新綁定到會員。
  - 不可再被新增至活動規則。
  - 既有 `member_tag_bindings` / `event_tag_rules` 保留歷史資料。
- Claim / 可見性檢核時，僅計算 **active tag**（以 catalog 的 `is_active = true` 為準）。

## 4. Domain / Application 設計

### 4.1 新增領域概念

1. `MemberTag`（或 Tag Catalog Aggregate）
   - 建立、改名、停用。
   - 保證 tenant+code 唯一。
2. `MemberTagBinding`
   - 支援會員 Tag replace（全量覆寫）。
3. `TicketClaimEventTagRule`
   - 活動允許 Tag 清單（ANY）。

### 4.2 既有 TicketClaimEvent 的規則補充

- 當活動無任何 tag rule：代表不限 Tag。
- 當活動存在 tag rule：會員需命中至少一個 active tag。
- `Active` 狀態下允許修改 Tag 條件。

### 4.3 Repository 介面建議

- `IMemberTagCatalogRepository`
  - `GetByCodeAsync(tenantId, tagCode)`
  - `GetByIdsAsync(tenantId, ids)`
  - `Insert/Update`
- `IMemberTagBindingRepository`
  - `GetTagIdsByMemberIdAsync(tenantId, memberId)`
  - `ReplaceMemberTagsAsync(tenantId, memberId, tagIds, operatorUserId, now)`
- `ITicketClaimEventTagRuleRepository`
  - `GetTagIdsByEventIdAsync(tenantId, eventId)`
  - `ReplaceEventTagRulesAsync(tenantId, eventId, tagIds, operatorUserId, now)`

## 5. API Contract（v1）

## 5.1 Admin - Tag Catalog

### POST `/admin/member-tags`
- Request
  - `tagCode: string` (1..64, normalize lowercase)
  - `displayName: string` (1..128)
- Response
  - `id, tagCode, displayName, isActive`

### PATCH `/admin/member-tags/{tagId}`
- 可修改 `displayName`

### POST `/admin/member-tags/{tagId}/deactivate`
- 停用 tag

### GET `/admin/member-tags?keyword=&isActive=&page=&pageSize=`
- 列表查詢

## 5.2 Admin - Member Tag Binding

### PUT `/admin/members/{memberId}/tags`
- Request
  - `tagIds: Guid[]`（全量覆寫）
- 行為
  - 僅允許 active tag
  - 寫審計

### GET `/admin/members/{memberId}/tags`
- 回傳 member 綁定 tags

## 5.3 Admin - TicketClaimEvent Tag Rule

### 建立活動 / 更新活動 Request 增加欄位
- `allowedTagIds: Guid[]`（可空；空即不限）

### GET 活動 detail / list
- 回傳 `allowedTagIds`

> `Update` 在活動 `Active` 狀態下可更新 allowedTagIds，並寫審計。

## 5.4 Frontend - 可見活動查詢

既有 endpoint（GetActiveTicketClaimEventsForMember）加入 tag 過濾規則：
- 活動無 tag rule -> 可見。
- 活動有 tag rule -> 會員與活動 active tags 交集非空才可見。

## 5.5 Claim API（核心授權）

Claim 處理流程中新增資格檢查：
1. 讀 event tag rules（active）。
2. 若空 -> pass。
3. 若非空 -> 讀 member active tags，做 ANY 比對。
4. 不符回傳 `Gaming.TicketClaimEventMemberTagNotEligible`。

## 6. 查詢與 SQL 策略（立即生效）

## 6.1 可見活動查詢 SQL 概念

在活動條件內加入：

```sql
(
  NOT EXISTS (
    SELECT 1
    FROM gaming.ticket_claim_event_tag_rules etr
    JOIN public.member_tags_catalog tc
      ON tc.id = etr.tag_id
     AND tc.tenant_id = etr.tenant_id
     AND tc.is_active = true
    WHERE etr.tenant_id = e.tenant_id
      AND etr.event_id = e.id
  )
  OR EXISTS (
    SELECT 1
    FROM gaming.ticket_claim_event_tag_rules etr
    JOIN public.member_tag_bindings mtb
      ON mtb.tenant_id = etr.tenant_id
     AND mtb.tag_id = etr.tag_id
    JOIN public.member_tags_catalog tc
      ON tc.id = etr.tag_id
     AND tc.tenant_id = etr.tenant_id
     AND tc.is_active = true
    WHERE etr.tenant_id = e.tenant_id
      AND etr.event_id = e.id
      AND mtb.member_id = @MemberId
  )
)
```

此做法可保證「會員 tag 變更後下一次查詢立即生效」。

## 6.2 Claim 時一致性

- Claim 仍須在交易內重複做 tag 檢核，避免 TOCTOU（查詢可見但領取時條件已變動）。

## 8. 驗證規則與錯誤碼

新增/調整錯誤碼建議：

- `Gaming.MemberTagNotFound`
- `Gaming.MemberTagInactive`
- `Gaming.MemberTagCodeDuplicated`
- `Gaming.TicketClaimEventMemberTagNotEligible`
- `Gaming.TicketClaimEventInvalidTagRule`

輸入驗證：
- `tagCode`：`^[a-z0-9_\-\.]{1,64}$`（建立時 normalize）
- `allowedTagIds` / `member tagIds` 不可重複
- 不可引用停用 tag

## 9. Migration 與上線策略

1. 新增三張表 + 索引 + FK。
2. 不影響既有功能：
   - 既有活動預設沒有 tag rules => 行為不變（不限 Tag）。
3. 先部署 schema，再部署應用程式。
4. 若需回滾，先回滾應用層邏輯，再保留資料表（避免資料遺失）。

## 11. 測試計畫（最小可交付）

### 11.1 Unit
- ANY 命中判斷（空規則/命中/不命中）
- 停用 tag 不可引用
- Active 活動可更新 tag rules

### 11.2 Integration
- 會員 tag 變更後，可見活動查詢立即變化
- 會員 tag 變更後，Claim 資格立即變化
- 活動更新 allowedTagIds 後，立即影響可見與可領

### 11.3 Regression
- 無 tag rule 的舊活動行為不變
- 票券領取配額、時間窗、scope 原規則不受影響

## 13. 驗收標準（DoD）

1. Tag 在租戶內唯一，重複 code 建立失敗。
2. Tag 停用後不可被新綁定/新規則引用。
3. 活動 active 狀態可修改 allowedTagIds，且有審計記錄。
4. 會員 tag 更新後：
   - 下次查詢可見活動立即變化。
   - 下一次 claim 資格立即變化。
5. P95 在目標流量下不劣於基線 + 20%（先以索引優化達成）。
