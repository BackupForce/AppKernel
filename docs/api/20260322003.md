# Admin Me API：取得目前登入者自身資訊

## 1. API 概要
- **Method / Path**：`GET /api/tenants/{tenantId}/admin/me/profile`
- **用途**：取得目前登入後台使用者自己的基本資訊。
- **驗證**：`Authorization: Bearer <JWT>`
- **授權規則**：沿用現有 `/admin/me` 群組設定，只要通過 `TenantUser` policy 並位於目前 tenant 內即可呼叫，不需要前端額外傳 `userId`。
- **Query / Body**：無。

## 2. Response DTO

```json
{
  "id": "4c9c2de8-1f89-4c6e-9d74-5b7f8e1ac001",
  "email": "admin@example.com",
  "name": "Tenant Admin",
  "hasPublicProfile": true,
  "isEnabled": true,
  "userType": 1,
  "tenantId": "11111111-1111-1111-1111-111111111111",
  "roles": [
    {
      "roleId": 1,
      "roleName": "TenantAdmin"
    }
  ]
}
```

### 欄位說明
- `id`：目前登入使用者的 User Id。
- `email`：使用者 Email。
- `name`：使用者名稱。
- `hasPublicProfile`：是否公開個人資料。
- `isEnabled`：帳號是否啟用。
- `userType`：使用者類型；此 API 目標為後台租戶使用者。
- `tenantId`：當前租戶 Id。
- `roles`：目前使用者已綁定角色清單。
  - `roleId`：角色 Id。
  - `roleName`：角色名稱。

## 3. 前端串接建議
- 初始化後台畫面或刷新登入狀態時，可先呼叫此 API 取得使用者名稱、Email、角色顯示資訊。
- 若還需要權限代碼清單，請再搭配既有 `GET /api/tenants/{tenantId}/admin/me/permissions` 一起使用。
- 本 API 僅回傳「自己」的資料，不接受指定其他 user 的參數。

## 4. 失敗情境
- `401 Unauthorized`：未登入或 JWT 無效。
- `403 Forbidden`：不符合後台租戶使用者授權條件。
- `404 Not Found`：JWT 對應的使用者不存在於目前 tenant。
